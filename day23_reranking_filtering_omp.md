## 4. Режимы работы

Поддержать следующие режимы:

### `no_rag`

- вопрос отправляется LLM без локального контекста;
- FAISS и SQLite чанков не используются.

### `baseline_rag`

- используется исходный вопрос;
- поиск выполняется непосредственно в FAISS;
- берётся обычный Top-K;
- Query Rewrite выключен;
- similarity-фильтр выключен;
- reranker выключен.

### `filtered_rag`

- используется исходный вопрос;
- выполняется широкий поиск кандидатов;
- применяется similarity threshold;
- отдельный reranker не используется.

### `enhanced_rag`

- выполняется Query Rewrite;
- поиск производится по исходному и переписанному запросам;
- результаты объединяются и дедуплицируются;
- применяется similarity-фильтр;
- применяется выбранный reranker;
- в LLM передаётся итоговый Final Top-K.

Главное сравнение задания:

```text
Baseline RAG против Enhanced RAG
```

Режим без RAG оставить как дополнительный контрольный режим.

## 7. Query Rewrite

Реализовать отдельный сервис:

```python
def rewrite_query(
    question: str,
    llm: LLMProvider,
    max_alternatives: int = 2,
) -> RewrittenQuery:
    ...
```

Задача Query Rewrite — сформировать поисковый запрос, а не ответить на вопрос.

Системный промпт:

```text
Преобразуй вопрос пользователя в запрос для семантического поиска
по локальной технической документации.

Правила:
1. Не отвечай на вопрос.
2. Сохрани исходный смысл.
3. Не добавляй неизвестные факты.
4. Не изменяй названия файлов, классов, функций, команд и параметров.
5. Раскрой местоимения только тогда, когда это возможно из текста вопроса.
6. Добавь полезные поисковые термины без изменения намерения пользователя.
7. Верни только JSON заданного формата.
```

Формат ответа:

```json
{
  "search_query": "переписанный запрос",
  "alternative_queries": [
    "альтернативный запрос 1",
    "альтернативный запрос 2"
  ]
}
```

Требования:

- валидировать JSON;
- удалить пустые и повторяющиеся варианты;
- ограничить число альтернатив настройкой;
- не использовать вариант, полностью совпадающий с исходным вопросом, как отдельную альтернативу;
- при тайм-ауте, ошибке LLM или невалидном JSON продолжить работу с исходным вопросом;
- сохранить причину fallback;
- Query Rewrite не должен быть обязательным для Baseline RAG;
- не использовать ответы модели rewrite как готовый контекст.

## 9. Объединение результатов

Для объединения нескольких ранжированных списков использовать Reciprocal Rank Fusion:

```text
RRF(chunk) = сумма 1 / (k + rank)
```

Значение `k` по умолчанию:

```text
60
```

Реализовать:

```python
def reciprocal_rank_fusion(
    ranked_lists: list[list[RetrievalCandidate]],
    k: int = 60,
) -> list[RetrievalCandidate]:
    ...
```

Сохранить `fusion_score`. При одинаковом fusion score использовать детерминированное дополнительное сравнение:

1. более высокая similarity;
2. лучшая исходная позиция;
3. `chunk_id`.

Если Query Rewrite выключен и используется только один запрос, допустимо сохранить исходную сортировку FAISS.

## 10. Similarity-фильтр

Реализовать:

```python
def filter_by_similarity(
    candidates: list[RetrievalCandidate],
    threshold: float,
) -> tuple[list[RetrievalCandidate], list[RetrievalCandidate]]:
    ...
```

Правила:

- чанк проходит фильтр, если `similarity >= threshold`;
- прошедшему чанку присваивается статус `accepted`;
- отклонённому чанку присваивается статус `rejected_similarity`;
- сохранить понятную причину отклонения;
- не менять исходный score;
- не поднимать автоматически чанк ниже порога только для заполнения Final Top-K.

Пример причины:

```text
Similarity 0.291 ниже установленного порога 0.350.
```

Если ни один чанк не прошёл порог, Enhanced RAG не должен передавать нерелевантный контекст LLM. Пользователь должен получить сообщение о недостатке релевантной информации.

## 14. HeuristicReranker

Реализовать локальный реранкинг без дополнительной нейросетевой модели.

Базовая формула:

```text
final_score =
    semantic_weight × semantic_score
  + lexical_weight × lexical_score
  + metadata_weight × metadata_score
```

Значения по умолчанию:

```text
semantic_weight = 0.70
lexical_weight = 0.20
metadata_weight = 0.10
```

Сумма весов должна быть равна 1 с допустимой погрешностью.

### Semantic score

Использовать нормализованную similarity из FAISS. Если текущая система допускает отрицательные значения, корректно привести их к диапазону, используемому формулой, и документировать преобразование.

### Lexical score

Вычислять пересечение значимых терминов вопроса и текста чанка:

- привести к нижнему регистру;
- выделить слова и технические идентификаторы;
- сохранить идентификаторы вроде `load_pdf`, `IndexFlatIP`, `streamlit run`;
- исключить минимальный набор стоп-слов;
- не требовать тяжёлой морфологии;
- вернуть значение от 0 до 1.

### Metadata score

Учитывать совпадения запроса с:

- именем файла;
- заголовком;
- секцией;
- именем класса или функции, если оно записано в `section`.

Точное совпадение технического идентификатора должно иметь больший вес, чем совпадение обычного слова.

После расчёта:

- сохранить все компоненты score;
- отсортировать по `final_score`;
- назначить `final_rank`;
- обеспечить детерминированный порядок при равных значениях.

- улучшил ли rewrite поиск;
- комментарий.

Повторное нажатие не должно создавать дубликат оценки одного запуска.

## 24. Сохранение результатов

Расширить хранилище RAG-результатов. Не менять базу метаданных индекса.

Для новых установок схема `rag_runs` должна содержать:

```sql
retrieval_mode TEXT,
original_query TEXT,
rewritten_query TEXT,
alternative_queries_json TEXT NOT NULL DEFAULT '[]',
candidate_top_k INTEGER,

rewrite_time REAL NOT NULL DEFAULT 0,
filter_time REAL NOT NULL DEFAULT 0,
rerank_time REAL NOT NULL DEFAULT 0
```

Диагностику кандидатов хранить отдельно:

```sql
CREATE TABLE IF NOT EXISTS retrieval_candidates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id INTEGER NOT NULL,
    chunk_id TEXT NOT NULL,
    source TEXT NOT NULL,
    section TEXT,
    original_rank INTEGER,
    final_rank INTEGER,
    similarity REAL NOT NULL,
    fusion_score REAL,
    lexical_score REAL,
    metadata_score REAL,
    rerank_score REAL,
    final_score REAL,
    status TEXT NOT NULL,
    rejection_reason TEXT,
    matched_queries_json TEXT NOT NULL DEFAULT '[]',
    FOREIGN KEY (run_id) REFERENCES rag_runs(id)
        ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_retrieval_candidates_run
ON retrieval_candidates(run_id);
```

Не дублировать полный текст чанка в базе результатов, если его можно получить по `chunk_id` из базы индекса. При недоступности старого индекса история всё равно должна показывать сохранённые scores и источник.

## 33. Обработка ошибок

Корректно обрабатывать:

- Query Rewrite вернул невалидный JSON;
- LLM для rewrite недоступна;
- rewritten query пустой;
- индекс отсутствует;
- `candidate_top_k < final_top_k`;
- threshold вне допустимого диапазона;
- ни один чанк не прошёл фильтр;
- reranker завершился ошибкой;
- CrossEncoder недоступен;
- SQLite не удалось мигрировать;
- старые записи не содержат новых полей;
- контрольный прогон прерван;
- один из режимов сравнения завершился ошибкой.

При сбое CrossEncoder предложить или автоматически применить heuristic reranker только при явном отображении fallback в UI и сохранении этой информации в результате.

## 34. Безопасность

- считать содержимое документов недоверенными данными;
- не выполнять инструкции, обнаруженные внутри чанков;
- не передавать документы как системный промпт;
- отделять контекст явными маркерами;
- не позволять Query Rewrite изменять системные правила;
- не записывать полный приватный контекст в лог;
- не принимать произвольные пути и имена таблиц из UI;
- не удалять данные без подтверждения;
- не отправлять документы внешнему LLM, если приложение заявлено как локальное.
