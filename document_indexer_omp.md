# Техническое задание: локальный индексатор документов

## 1. Роль исполнителя

Ты — опытный Python-разработчик. Необходимо реализовать законченное учебное приложение для локальной индексации документов, семантического поиска и визуального сравнения двух стратегий разбиения текста на чанки.

Приложение должно запускаться локально, не требовать внешней базы данных и предоставлять веб-интерфейс, чтобы пользователь мог работать с ним без консоли.

## 2. Цель проекта

Создать приложение, которое:

1. Загружает документы разных форматов.
2. Извлекает и нормализует текст.
3. Разбивает текст двумя способами:
   - по фиксированному размеру;
   - по структуре документа.
4. Генерирует эмбеддинги локальной моделью.
5. Сохраняет векторный индекс и метаданные локально.
6. Выполняет семантический поиск.
7. Показывает пользователю содержимое чанков и этапы индексации.
8. Сравнивает результаты двух стратегий chunking.

## 3. Технологии

Использовать следующий стек:

- Python 3.11 или новее;
- Streamlit — веб-интерфейс;
- Sentence Transformers — генерация эмбеддингов;
- модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`;
- FAISS CPU — поиск по векторам;
- SQLite — хранение текстов и метаданных;
- PyPDF — извлечение текста из PDF;
- стандартный модуль `ast` — структурный разбор Python-кода;
- Pandas и Plotly — таблицы и графики;
- Pytest — автоматические тесты.

Приложение должно работать без платных API. После первоначальной загрузки модели индексация и поиск должны выполняться локально.

## 4. Поддерживаемые документы

Обязательные форматы:

- `.pdf`;
- `.md`;
- `.txt`;
- `.py`.

Дополнительно можно поддержать:

- `.rst`;
- `.json`;
- `.yaml` и `.yml`;
- `.js` и `.ts` как обычный текст.

Приложение должно корректно обрабатывать набор документов суммарным объёмом не менее 20–30 страниц текста.

## 6. Модель данных

Создать тип данных `Document` со следующими полями:

```python
@dataclass
class Document:
    document_id: str
    source: str
    title: str
    file_type: str
    text: str
    page_number: int | None = None
```

Создать тип данных `Chunk`:

```python
@dataclass
class Chunk:
    chunk_id: str
    document_id: str
    source: str
    title: str
    section: str | None
    strategy: str
    content: str
    token_count: int
    page_number: int | None = None
    start_position: int | None = None
    end_position: int | None = None
```

Идентификаторы должны быть детерминированными. Для их формирования можно использовать SHA-256 от пути, стратегии, номера секции и позиции чанка.

## 7. Загрузка и извлечение текста

В `src/loaders.py` реализовать единый интерфейс:

```python
def load_document(path: Path) -> list[Document]:
    ...
```

Требования по форматам:

### PDF

- извлекать текст отдельно с каждой страницы;
- сохранять номер страницы;
- пропускать пустые страницы;
- выводить понятное предупреждение, если PDF не содержит извлекаемого текста;
- OCR не является обязательным.

### Markdown

- сохранять заголовки;
- не удалять содержимое блоков кода;
- корректно обрабатывать UTF-8.

### TXT

- читать UTF-8;
- при ошибке кодировки показать понятное сообщение пользователю.

### Python

- загружать полный исходный код;
- структурный chunking должен находить функции, асинхронные функции и классы через `ast`;
- сохранять имена найденных сущностей в поле `section`.

## 8. Нормализация текста

Реализовать безопасную нормализацию:

- заменить Windows-переносы строк на `\n`;
- удалить лишние пробелы в конце строк;
- сократить последовательности из трёх и более пустых строк;
- не объединять все абзацы в одну строку;
- не изменять содержимое исходного кода;
- не удалять заголовки Markdown.

## 9. Стратегия chunking №1: фиксированный размер

Реализовать функцию:

```python
def chunk_fixed(
    document: Document,
    chunk_size: int = 500,
    overlap: int = 80,
) -> list[Chunk]:
    ...
```

Требования:

- размер измеряется в токенах токенизатора модели эмбеддингов;
- значение `overlap` должно быть меньше `chunk_size`;
- значения по умолчанию: 500 токенов и overlap 80 токенов;
- последний непустой фрагмент не отбрасывать;
- сохранять начальную и конечную позиции;
- присваивать стратегии значение `fixed`.

## 10. Стратегия chunking №2: по структуре

Реализовать функцию:

```python
def chunk_structural(
    document: Document,
    max_chunk_size: int = 700,
    overlap: int = 80,
) -> list[Chunk]:
    ...
```

Правила:

### Markdown

- разделять документ по заголовкам `#`–`######`;
- записывать путь заголовков в `section`, например `Установка > Docker`;
- заголовок должен оставаться в тексте соответствующего чанка.

### Python

- верхнеуровневые функции и классы превращать в отдельные смысловые блоки;
- модульный код до первой функции сохранять как отдельную секцию;
- для методов использовать секцию вида `ClassName.method_name`;
- при ошибке синтаксического анализа использовать разбиение по абзацам или строкам.

### PDF и TXT

- использовать пустые строки и короткие строки, похожие на заголовки, как границы разделов;
- для PDF учитывать номер страницы;
- не объединять текст разных страниц без сохранения номера страницы.

### Большие разделы

Если структурный раздел превышает `max_chunk_size`, дополнительно разбивать его фиксированным способом, сохраняя исходное значение `section`.

Стратегия каждого полученного чанка должна иметь значение `structural`.

```python
class EmbeddingService:

        ...

    def encode_query(self, query: str) -> np.ndarray:
        ...
```

Требования:

## 12. FAISS-индекс

Для нормализованных векторов использовать `faiss.IndexFlatIP`, чтобы inner product соответствовал косинусному сходству.

Для каждой стратегии создать отдельный каталог:

```text
indexes/fixed/
├── vectors.faiss
├── metadata.sqlite
└── manifest.json

indexes/structural/
├── vectors.faiss
├── metadata.sqlite
└── manifest.json
```

В `manifest.json` сохранить:

- название стратегии;
- название модели;
- размерность эмбеддингов;
- дату создания;
- количество документов;
- количество чанков;
- параметры chunking;
- время индексации.

Индекс записывать сначала во временный файл, а затем атомарно заменять итоговый файл, чтобы не оставлять повреждённый индекс при ошибке.

## 13. SQLite

Создать таблицу:

```sql
CREATE TABLE IF NOT EXISTS chunks (
    vector_id INTEGER PRIMARY KEY,
    chunk_id TEXT UNIQUE NOT NULL,
    document_id TEXT NOT NULL,
    source TEXT NOT NULL,
    title TEXT,
    section TEXT,
    strategy TEXT NOT NULL,
    content TEXT NOT NULL,
    token_count INTEGER NOT NULL,
    page_number INTEGER,
    start_position INTEGER,
    end_position INTEGER
);

CREATE INDEX IF NOT EXISTS idx_chunks_source
ON chunks(source);

CREATE INDEX IF NOT EXISTS idx_chunks_strategy
ON chunks(strategy);
```

Значение `vector_id` должно строго соответствовать идентификатору вектора в FAISS.
